# Watermelon

</div>

A work in progress Minecraft server written in C++ aiming to be fast and easily customizable. The goal of Watermelon is to work like a real Minecraft server while being way faster and having more features.

Target version: Minecraft Java Edition **26.3** (protocol 777).

## What's working right now?

Only a few bits are working right now: the architecture of the project is still being worked on, and features take time to be implemented because almost nothing is already built.

Configuration:
- Enabling the java server
- Java server address and port
- Some java server properties like view and simulation distance, max player count and motd
- Some logger properties like the file where to write logs and the minimum level to log

Networking:
- The TCP stack to communicate with Minecraft clients
- Parsing and serializing of java packets
- Basic server status/ping
- Basic login and configuration sequence

## Building

### Prerequisites

| Tool | Version | Why |
| --- | --- | --- |
| C++ compiler | GCC 13+, or Visual Studio 2022 17.2+ (MSVC 19.32+) | C++23: `std::byteswap`, `std::bit_cast`, `<format>` and `std::chrono` time zones |
| CMake | 3.20+ | Build system |
| Ninja | any recent version | Generator used by the provided presets |
| Python | 3.9+ | Registry and tag header generation (see below) |
| `nbtlib` | latest (`pip install nbtlib`) | Used by `codegen/synchronizedRegistries.py` |
| Java | the version required by the Minecraft 26.3 server jar | Only to run Mojang's data generator |

Tested with GCC 13.3 on Ubuntu 24.04 and MSVC on Windows. Clang and macOS are untested for now.

All third-party libraries (toml++, nlohmann/json) are bundled in `include/Utils`, nothing else needs to be installed.

### 1. Generate the registry and tag headers

Three headers are generated from Mojang's own data. `include/Registry/BuiltIn.h`, `include/Registry/Synchronised.h` and `include/Tag/Tags.h`. They are not in the repository and must be generated by yourself.

1. Download the Minecraft 26.3 server jar.
2. Run the official data generator (adjust the command if its syntax changed in this version):

   ```bash
   java -DbundlerMainClass=net.minecraft.data.Main -jar server.jar --server --reports --output generated
   ```

   This creates `generated/data/` and `generated/reports/registries.json`.
3. Install the Python dependency:

   ```bash
   pip install nbtlib
   ```
4. From the **root of the repository** (the scripts write to relative paths), run the scripts **in this order**:

   ```bash
   python codegen/builtInRegistries.py generated/reports/registries.json
   python codegen/synchronizedRegistries.py generated/data
   python codegen/tags.py generated/data generated/reports/registries.json
   ```

   `synchronizedRegistries.py` writes `protocol_mapping.json`, which `tags.py` reads, so the order matters.

The data must come from **the same version as the clients** that will connect. Registries that are missing or generated from another version make the client disconnect at the end of the configuration phase (for example with `Missing element ResourceKey[minecraft:block_transformer / minecraft:shovel]`).

If `BuiltIn.h` or `Synchronised.h` do not exist when CMake configures the project, empty stubs are created in the build directory so the project still compiles. The server then starts, but **no client will be able to join**. Run the scripts above, then build again.

### 2. Compile

Linux:

```bash
cmake --preset linux-release
cmake --build build/linux-release
```

Windows (from a Visual Studio developer prompt, or directly from Visual Studio):

```bash
cmake --preset windows-release
cmake --build build/windows-release
```

## Running

Run the server from the directory where you want its files to be created:

```bash
./out/build/linux-debug/Watermelon
```

On the first launch it creates `watermelon.toml` with the default configuration, and writes its logs to `latest.log`.

Encryption is not implemented yet, so set this in `watermelon.toml` before trying to join:

```toml
[networking.java]
online_mode = false
```

## Troubleshooting

- **`Registry/BuiltIn.h: No such file or directory`**: the generated headers are missing, follow [Generate the registry and tag headers](#1-generate-the-registry-and-tag-headers).
- **The client disconnects after the configuration phase with a `Missing element ResourceKey[...]` error**: the registry data sent by the server is incomplete or comes from another version, regenerate the headers.
- **`Address already in use`**: another process is using the port, or the previous server instance has not been fully released yet.
